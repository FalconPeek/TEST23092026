# T-005 worker report

## Summary
Group/invite/member/player Server Actions wrapping every RPC in `20260923055124_group_rpcs.sql`,
a pure `mapDbError` helper translating the `PICADO_<CODE>:` error prefixes to Spanish copy,
and the `errors`/`groups` message namespaces.

## Files changed
- `messages/es.ts` — added `errors` (10 keys: unauthenticated, forbidden, notMember,
  inviteInvalid, inviteExpired, inviteRevoked, inviteUsedUp, validation, ownerCannotLeave,
  ownerCannotBeRemoved) and `groups` (12 toast-copy keys) namespaces, exact strings from the
  task spec. Did not touch any existing namespace; T-001's "15 positions / 34 attributes"
  test is unaffected.
- `lib/actions/errors.ts` (new) — `mapDbError({message}?)`: prefix-matches
  `PICADO_NOT_MEMBER:` / `PICADO_INVITE_INVALID:` / `PICADO_FORBIDDEN:` / `PICADO_VALIDATION:`,
  then substring-matches known details (`revoked`, `expired`, `usage limit` for invites;
  `transfer ownership before leaving`, `owner cannot be removed` for forbidden) to the
  specific `es.errors.*` string; anything else (including `null`/`undefined`) →
  `es.common.error`. Exact substrings taken directly from
  `supabase/migrations/20260923055124_group_rpcs.sql`'s `raise exception` texts.
- `lib/actions/errors.test.ts` (new) — one test per branch (11 tests): null/undefined,
  unknown message, each of the 4 prefixes, each of the 3 invite-detail branches, and both
  forbidden-detail branches.
- `lib/actions/groups.ts` (new, `'use server'`) — one exported function per RPC listed in
  the task (14 total): `createGroup`, `updateGroup`, `createInvite`, `revokeInvite`,
  `acceptInvite`, `setMemberRole`, `transferOwnership`, `removeMember`, `leaveGroup`,
  `addGuestPlayer`, `claimGuestPlayer`, `assignGuestPlayer`, `updateMyPlayer`,
  `updatePlayer`. Every one: zod-parse the plain input object → `getUserId()` (never
  `getSession()`) → `createClient()` (session client, never admin) → `supabase.rpc(name,
  {p_*})` with args matching the generated `Database["public"]["Functions"]` signatures →
  on error, `fail(mapDbError(error))` → on success, `revalidatePath("/g")` or
  `revalidatePath(\`/g/${groupId}\`)` → typed `ActionResult`.
  - `role` inputs for `createInvite`/`setMemberRole` are `z.enum(["member","spectator","admin"])`
    — `"owner"` is not a member of the enum, so it's rejected at parse time regardless of
    what the RPC itself also enforces.
  - `createInvite`'s `expiresInDays`/`maxUses` are `number | null` (not optional): `null`
    means "no expiration"/"no limit" and is sent as an **explicit** `null` to
    `p_expires_at`/`p_max_uses` so Postgres stores `NULL` rather than falling back to the
    RPC's own default (`now() + 7 days`) — omitting the key entirely would trigger that
    default instead, which is a different meaning. The generated `Args` type for those
    params is `?: string`/`?: number` (optional, not nullable) since codegen only sees a
    SQL `DEFAULT` clause, not nullability; cast at the call site
    (`as unknown as string | undefined`, similarly for maxUses) to keep this intentional
    behavior without touching the generated file.
  - `updateGroup` re-validates `settings` with `groupSettingsSchema` (defaults applied) and
    sends the *parsed* object as `p_settings` (cast `as unknown as Json`, since zod's
    inferred `GroupSettings` type isn't structurally declared as the generated `Json` union
    even though every value in it is JSON-safe).
  - `updateMyPlayer`/`updatePlayer` share a `playerFieldsShape` object spread into two
    separate `z.object(...).refine(...)` schemas (couldn't `.extend()` after `.refine()`,
    and didn't want a generic-typed shared refine helper that would need `any`), and a
    typed `altPositionsValid()` helper (no `any`) enforcing "max 4, unique, excludes the
    primary position" — the DB helper (`private.apply_player_update`) only validates
    display-name length and height range, so this really is client-side-only enforcement
    per the task's instructions.
- `lib/actions/groups.test.ts` (new) — mocks `@/lib/supabase/server`
  (`createClient` → `{ rpc: mockRpc }`, `getUserId` → `mockGetUserId()`) and `next/cache`
  (`revalidatePath` → `mockRevalidatePath`); 35 tests covering: invalid input never calls
  rpc (createGroup empty name, updateGroup bad uuid, createInvite role "owner",
  updateMyPlayer duplicate/primary-clashing alt positions), unauthenticated short-circuits
  before rpc (createGroup, updateMyPlayer), happy-path calls the exact RPC name with the
  exact `p_*` args for all 14 actions, RPC errors are mapped through `mapDbError` and never
  leaked raw (validation/forbidden/invite-expired/owner-cannot-be-removed/
  owner-cannot-leave cases), and `updateGroup` applies `defaultGroupSettings` for an empty
  settings object.

## Notes / gotchas
- Test UUIDs must satisfy zod v4's strict `z.uuid()` pattern (version nibble `1-8`, variant
  nibble `8/9/a/b`) — naive `"1111...1111"`-style placeholders fail validation with
  "Invalid UUID". Used `...-4111-8111-...`-shaped constants instead. Cost some debugging
  time (14 tests initially failed with a validation error that looked like it came from
  somewhere else); worth remembering for future test UUIDs in this repo.
- Reused the `mockFoo` naming convention from Vitest's hoisting rules (`vi.mock()` factories
  can only reference outer variables whose name starts with `mock`) — used
  `mockRpc`/`mockGetUserId`/`mockRevalidatePath`, not `rpcMock`/etc.
