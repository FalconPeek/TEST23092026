# T-003 worker report

## Summary
Login page + auth Server Actions (OAuth, magic link, password, sign-out), the auth
error page, and the interactive login form with tests.

## Files changed
- `lib/actions/result.ts` (new) — `ActionResult<T>`, `ok()`, `fail()`.
- `lib/actions/auth.ts` (new, `'use server'`) — `signInWithOAuth`, `sendMagicLink`,
  `signInWithPassword`, `signOut`. All zod-validated, all redirect targets go through
  `safeNextPath`, all errors return typed `fail(...)` with copy from `messages/es.ts`
  (never a raw Supabase error). `callbackUrl()` builds `${siteUrl()}auth/callback?next=...`
  shared by OAuth and magic-link redirect targets.
- `app/login/page.tsx` (new) — Server Component; `searchParams` awaited per Next 16
  (`PageProps<"/login">`); redirects already-signed-in users (`getUserId()`) to
  `safeNextPath(next)`; renders `<LoginForm next={...} />`.
- `components/auth/login-form.tsx` (new, `'use client'`) — OAuth buttons (Google/Discord)
  wrapped in `useTransition`, showing `es.common.error` via a `sonner` toast on failure;
  `Tabs` ("Link mágico" / "Contraseña") each with a `useActionState` form
  (`sendMagicLink` / `signInWithPassword`), inline error text, and the magic-link success
  message. Both forms have `noValidate` — native HTML5 constraint validation was left off
  so the zod-validated Server Action is always the source of truth for errors (also avoids
  the browser silently swallowing submission before the action runs).
- `components/auth/login-form.test.tsx` (new) — Testing Library test mocking
  `@/lib/actions/auth` via `vi.mock`; verifies both tabs + OAuth buttons render, and that
  an invalid email on the magic-link form surfaces `es.auth.invalidEmail`. Added an
  explicit `afterEach(cleanup)` in this file since no repo-wide RTL cleanup convention
  existed yet (vitest.config.ts has no `test.globals: true`, so RTL's auto-cleanup hook
  isn't registered) — otherwise the two tests' renders collide in the same DOM.
- `app/auth/auth-code-error/page.tsx` (new) — centered `codeErrorTitle`/`codeErrorBody`
  with a button back to `/login`.

## Notes / assumptions
- `es.auth` already had every key the task needed (`emailLabel`, `passwordLabel`, etc.)
  from T-001 — no gaps found, nothing added to `messages/es.ts`.
- `signInWithOAuth` validates `provider` with `z.enum(["google","discord"])` even though
  the type already constrains it, since it's a Server Action and can be invoked with any
  payload from the client boundary.
- OAuth buttons call the action directly (not via `<form action>`) since there's no form
  data to collect; wrapped in `useTransition` to get a pending state and to catch the
  `fail(...)` result for the toast without blocking on a full page transition.
- `redirect()` calls are made outside of any try/catch, per Next's docs (it throws
  `NEXT_REDIRECT` internally) — verified no code path in `lib/actions/auth.ts` wraps them.
- Login page title uses the layout's `%s · Picado` template (`es.auth.title` becomes
  "Entrá a Picado · Picado"), consistent with T-002's metadata setup.
