# T-011 worker report

## Summary
Built the player profile page: FUT card (size lg), a face-stat radar, a top-5 "media por
posición" chips row, a match-stats tile row, and the grouped attribute list with colored
bars — all fed by a new pure `lib/cards/to-card-props.ts` mapper. Linked the group home's
member-preview avatars to their profile pages.

## Files changed
- `lib/cards/to-card-props.ts` (new) — `toCardProps(player, cardRow | null, playstyleLabels)`.
  Validates `face` jsonb against two exact-shape zod object schemas (outfield vs GK; disjoint
  key sets, so no ambiguity) and returns `null` for anything that matches neither. Validates
  `position` against `POSITIONS` (`lib/rating/positions.ts`) and `tier` against `TIERS`
  (`lib/rating/tiers.ts`) rather than re-deriving those lists locally, so this stays a single
  source of truth. `playstyles` jsonb is validated as `{code, plus}[]`, then filtered through
  `isPlayStyleCode` (drops anything not in the known 30) and labelled from the caller-supplied
  `playstyleLabels` map (falls back to the raw code if a label is missing) — kept as an
  explicit parameter rather than importing `es.playstyles` internally, per the task's given
  signature, so the module has no dependency on `messages/es.ts`. Star votes clamp to 1-5,
  defaulting to 3 when `null` (no votes yet).
- `lib/cards/to-card-props.test.ts` (new) — null row, outfield, GK, malformed face jsonb,
  invalid position, invalid tier, star clamping/defaulting, and playstyle
  filtering/label-fallback (9 tests).
- `messages/es.ts` — added `playstyles.*` (all 30 codes, task's exact Spanish labels) and
  `profile.*` (the 12 keys the task listed, plus two small additions needed to keep every
  string sourced from `es.ts`: `profile.votes(n)` — a compact "N votos" pluralizer for each
  attribute row's rater count, since `profile.raters(n)` is the longer "Votado por N
  compañeros" phrasing used near the card itself — and `profile.goalkeeper` = "Arquero" for
  the GK attribute group heading, which step 4 requires but step 2's message list didn't
  actually include a key for).
- `components/charts/face-stats-radar.tsx` (new) — `'use client'`, `RadarChart` via the
  shadcn `ChartContainer` wrapper, domain fixed to `[0, 99]` via a hidden `PolarRadiusAxis`,
  colored with `var(--color-tier-{tier}-accent)` (accepts `"provisional"` as a tier value
  too, matching the token set already defined for the card itself). Renders a parallel
  `sr-only` `<ul>` of "label: value" for accessibility, per the task.
- `components/player/attribute-list.tsx` (new) — server-safe (no `'use client'`, no
  interactivity). Groups outfield attributes via `subAttributesOfFaceStat` for each of the 6
  `OUTFIELD_FACE_STATS`, heading each group with the same `es.card.faceStats` label already
  used on the card face (RIT/TIR/PAS/REG/DEF/FIS) for visual consistency; adds a 7th
  "Arquero" group with `GK_ATTRIBUTES` only when `isGoalkeeperPosition(position)`. Each row:
  label, a width-percentage colored bar (`<50` red / `<65` amber / `<75` lime / else green —
  plain Tailwind palette classes, no new design tokens needed), the numeric value, and
  `profile.votes(nRaters)`. Silently skips any attribute with no matching row instead of
  crashing (defensive; in practice `recompute.ts` writes a row for every in-scope attribute
  regardless of vote count, so this shouldn't happen, but the component doesn't assume it).
- `components/player/attribute-list.test.tsx` (new) — grouping (outfield attrs appear under
  the right face-stat heading), GK group presence/absence by position, the 4 bar-color
  thresholds (read back each bar's `className` via its inline `width` style as the lookup
  key), and the missing-row skip (4 tests).
- `app/g/[groupId]/jugadores/[playerId]/page.tsx` (new) — loads the player (404s if the row
  doesn't exist or belongs to a different group — no `left_at` check, since a departed
  member's historical card/stats should stay viewable to the group, matching how the rest of
  the app treats left players as history, not deletion), then `player_cards`,
  `attribute_ratings` and `match_stats` in parallel. `match_stats` aggregates
  (matches/goals/assists/MVPs/clean sheets/average `median_rating`) are computed in TS from
  the raw rows rather than a DB aggregate query — `match_stats` only ever holds rows for
  finalized matches (per the Context note), so no extra status filter is needed, and the
  per-group row count is small enough that client-side reduction is simpler than a bespoke
  RPC. "Votar" is hidden for the viewer's own player; "Editar perfil" (the existing T-009
  route) shows only for the viewer's own player, matched by `player.user_id === userId`
  (correctly `false` when `user_id` is `null`, i.e. an unclaimed guest — nobody sees an edit
  link for a guest they don't own). Card, radar, position-OVR chips and attribute list are
  all wrapped in one `cardProps &&` guard, and the stat tiles have their own independent
  empty state — matching the task's "empty states when there's no card **or** no stats" as
  two genuinely independent conditions, not one combined check.
- `app/g/[groupId]/page.tsx` — each avatar in the member preview now links to
  `/g/[id]/jugadores/[pid]` instead of the whole `AvatarGroup` linking to `/ajustes`. Since
  `AvatarGroup`'s overlap/ring styling (`-space-x-2`, `*:data-[slot=avatar]:ring-2`) targets
  **direct children** only, wrapping each `Avatar` in a `Link` would silently break that
  styling (the `Avatar` would no longer be a direct child of the group `div`) — kept the
  `Link` as the direct child instead and moved the equivalent `ring-2 ring-background
  rounded-full` classes onto it directly. The heading above the avatars ("N miembros") keeps
  its own link to `/ajustes`, now separate from the avatar row instead of wrapping it.
