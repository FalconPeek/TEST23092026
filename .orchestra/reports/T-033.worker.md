# T-033 worker report

## What changed

1. **Stepper accessible names** (`components/tournament/match-admin-menu.tsx` + test): the score/pens −/+ `Stepper` buttons now get `aria-label={es.match.decrease(label)}`/`es.match.increase(label)` (same keys/pattern already used in `score-form.tsx`/`stat-row.tsx`). Score steppers use the team's label; penalty steppers use `` `${label} · ${es.bracket.pens}` `` so a team's score stepper and its penalty stepper never share an accessible name. Updated the existing "shows penalty fields only once tied" test (it queried `+` buttons by literal `"+"`, which is no longer the accessible name) and added a test asserting every stepper button in the result dialog has a distinct, non-empty name.

2. **Format card selected ring** (`components/tournament/create-tournament-form.tsx` + test): the card's `has-[[data-checked]]:ring-2` never matched — Radix's `RadioGroupItem` sets `data-state="checked"|"unchecked"`, never `data-checked` (confirmed by reading `@radix-ui/react-radio-group`'s source; `components/ui/radio-group.tsx`'s own `data-checked:` styling has the same latent issue, but that file is a shadcn primitive outside this task's scope and wasn't touched). Changed the selector to `has-[[data-state=checked]]:ring-2`/`ring-primary`. Added a test asserting the className string targets the real attribute and that clicking a different format flips `data-state` between cards (jsdom has no real CSS engine, so this — plus the classname assertion — is the meaningful thing to assert; it can't verify the ring visually renders).

3. **Crest cleanup** (`components/clubs/club-form.tsx` + test): both crest-mutating paths now remove the orphaned Storage object, best-effort (`.catch(() => {})`, never blocking the save that already succeeded):
   - Uploading a new crest with a different extension than the current `crestPath` removes the old object after `updateClub` succeeds (same extension = same object key, so `upsert: true` already overwrites it in place — no removal needed or attempted there).
   - "Quitar escudo" now removes the object in Storage, not just clearing `crest_path`.
   - 3 new tests: different-extension replacement removes the old object, same-extension replacement removes nothing, and removing the crest deletes its object.

4. **Squad editor empty-candidates copy** (`components/squads/squad-editor.tsx`, `messages/es.ts`): added `squads.noCandidates` ("No quedan jugadores disponibles.") and used it instead of the borrowed `es.clubs.empty` ("Todavía no hay clubes.") when a slot's bottom sheet has no eligible players left. 1 new test (fills every other slot, opens one more, asserts the new copy shows).

5. **List-query errors must not look like empty lists** (`app/g/[groupId]/plantillas/**`, `app/g/[groupId]/clubes/**`): every list-shaped Supabase query (`.select()` without `.maybeSingle()`, plus the `squad_likes` head-count query) in these 5 pages now destructures `error` alongside `data` and `throw`s it immediately, so a real query failure hits Next's error boundary instead of silently falling back to `?? []` and rendering "Todavía no hay plantillas/clubes." Left every `maybeSingle()` call's null-means-not-found handling untouched, per the task.
