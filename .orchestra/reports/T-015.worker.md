# T-015 worker report

## Summary
Implemented the match detail "disputes, finalize button, final result & stats" slice:
- Added `match.*` strings to `messages/es.ts` (disputedTitle, disputedBody, resolve, resolveHelp,
  finalizeNow, finalizeConfirm, finalized, mvp, cleanSheet, medianRating, waitingRatings).
- Extracted the per-player stat row (avatar + name + G/A/AG/atajadas steppers) out of
  `stats-form.tsx` into a new shared `components/match/stat-row.tsx` (`PlayerStatRow` +
  `MiniStepper`), and updated `stats-form.tsx` to use it. Same DOM structure preserved, so the
  existing `stats-form.test.tsx` (T-021/T-022 tap-target regressions) keeps passing unmodified.
- New `components/match/resolve-dispute-form.tsx` (admin-only, for `disputed` matches): team-score
  steppers + optional per-player stat override table built from `PlayerStatRow`, tracks which
  player rows were actually edited, and only sends those as `stats` overrides to `resolveDispute`
  (untouched rows are omitted, matching the RPC's "only override what you touch" semantics).
  Confirm dialog before submitting. Test: `resolve-dispute-form.test.tsx` (edited-only payload,
  and `stats: undefined` when nothing was touched).
- New `components/match/finalize-button.tsx` (admin-only, `reporting`/`pending_finalize`): confirm
  dialog → `finalizeMatchNow` → success/warning/error toast based on `outcome.status` (finalized,
  optionally with a `tournamentSyncError` warning toast; or disputed) → `router.refresh()`.
- New `components/match/match-result.tsx` (server-safe, no `"use client"`): scoreline with optional
  team color dots and penalty-shootout formatting (`"4-3 pen."`), and a per-team stats table
  (G/A/AG/atajadas/puntaje) with the MVP row tinted + a star badge ("Figura") and a clean-sheet
  shield icon (`aria-label` = `es.match.cleanSheet`), player rows link to `/g/[groupId]/jugadores/[playerId]`.
  Tests: `match-result.test.tsx` (scoreline, pens formatting, MVP badge, clean-sheet shield).
- Wired all three into `app/g/[groupId]/partidos/[matchId]/page.tsx`:
  - Added `match_results`/`match_stats` reads alongside the existing queries and built
    `matchResultStats` from `match_stats` joined against the already-fetched participants.
  - `disputed` → banner always shown; `ResolveDisputeForm` additionally shown to admins (prefilled
    from the same `myScoreReport`/`statPrefill` the reporting form uses — admins can't read other
    reporters' raw values per the reports RLS `select own rows only`, so they enter authoritative
    values from scratch, matching CLAUDE.md's "organizer enters authoritative values").
  - `pending_finalize` with the rating window closed now shows `waitingRatings(date)` instead of
    the participant-facing `windowClosed` message (that branch is system-wide, not user-specific).
  - `finalized` → renders `MatchResult` from `match_results`/`match_stats` only; the
    reporting/rating forms were already gated to `reporting`/`pending_finalize` so they're
    naturally hidden once finalized.
  - `FinalizeButton` shown to admins for `reporting`/`pending_finalize`.
- `app/g/[groupId]/partidos/page.tsx`: match cards already showed the reconciled score; added
  `pens1`/`pens2` to the query and scoreline so shootout results show `"X - Y (P-P pen.)"` there
  too.

  because the local Supabase stack was not running in this session and starting it wasn't in
  scope for this task; the build + full unit/component suite are green, and the Chrome browser

  history), so UI verification is limited to build output + component tests as before.
- `resolveDispute`'s per-player prefill/initial score comes from the admin's own prior
  score/stat reports (same source `StatsForm`/`ScoreForm` use), not from other reporters' raw
  values — RLS on `score_reports`/`stat_reports` restricts select to the reporter's own rows even
  for admins, so there is no read model exposing the conflicting raw numbers. If FATHER wants
  admins to see a breakdown of what was reported (anonymized or not) to help them decide the
  authoritative score, that would need a new SECURITY DEFINER RPC — flagging in case that's
  expected but out of scope for what T-015 specified.
- `finalize-button.tsx` only takes `matchId` (no `groupId`) since `finalizeMatchNow` doesn't need
  it and it's unused otherwise (kept the component lean; the calling page already knows
  `groupId`/`matchId` and revalidates server-side).
