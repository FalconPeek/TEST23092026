# T-031 worker report

## What changed

- `messages/es.ts`: added `matches.lineupModeList`, `matches.lineupModePitch`, `matches.applyLineup`, `matches.applyLineupConfirm`, `matches.lineupApplied`, `matches.pickClub`, `matches.needBothSides`.
- `components/squads/squad-editor.tsx`: added lineup-mode support without changing dream behavior:
  - new optional props `kind` (default `"dream"`), `matchId`, `side`, `excludePlayerIds`, `onAssignmentChange`.
  - `handleSave` now passes `kind`/`matchId`/`side` through to `saveSquad` instead of hardcoding the dream values; on success a `kind === "lineup"` save always `router.refresh()`s (there's no `/plantillas/[id]` page for a lineup squad — that route 404s on non-`dream` squads).
  - team size is a fixed read-only label instead of the `Select` when `kind === "lineup"` (the match dictates it); the club-select label switches to `es.matches.pickClub` in lineup mode.
  - the Publish/Unpublish/Share/Delete section is gated to `kind === "dream"` (published/likes/sharing are dream-squad-only concepts).
  - the bottom-sheet candidate list now also filters out `excludePlayerIds`, and a `useEffect` reports the current slot→playerId assignment up via `onAssignmentChange` whenever it changes, so two editors on the same page can cross-exclude each other's picks live.
- `components/squads/lineup-pitch-editors.tsx` (new, unlisted — see below): renders the two `SquadEditor`s (side 1 / side 2) side by side, wiring each one's `onAssignmentChange` into the other's `excludePlayerIds` (live cross-exclusion, not just after a save), plus the "Usar estas alineaciones" button (disabled until both sides have a saved squad id) with a confirm dialog that calls `applyLineupSquads` and redirects to the match page on success. Each editor is keyed by its squad id (`key={side1.squadId ?? "new-side-1"}`) so that once a side's first save creates its squad row and the page refreshes, the editor remounts with that id as its real `squadId` for subsequent saves (update instead of insert) — safe because a remount only ever happens right after a successful save, when local and server state already match.
- `app/g/[groupId]/partidos/[matchId]/equipos/page.tsx`: added the Lista/Cancha segmented toggle (`?modo=cancha`, same link-chip pattern as the rankings page's metric toggle). Cancha mode loads the squad context (`loadSquadContext`), the group's clubs, and any existing `kind: "lineup"` squads for this match (one query, filtered by `match_id` + `kind`, split by `side`), then renders `LineupPitchEditors`. Lista mode is untouched (same query and `LineupEditor` render as before, just wrapped with the mode toggle above it).
- `app/g/[groupId]/partidos/[matchId]/page.tsx`: `match_teams` select now also fetches `club_id`; when set, resolves the club's crest/colors and shows a small `ClubCrest` next to each team's name in the header `<h1>`. Renders nothing when `club_id` is null (today's default), per the task's "keep the change minimal."

## Notes for Verifier

- "Both sides saved" for enabling the apply button is computed server-side (`!!side1.squadId && !!side2.squadId`) and passed straight through as a prop read directly in JSX — not seeded into `useState` — so it stays correct across the `router.refresh()`s that follow each side's save, without needing any cross-component callback for that specific piece.
- Live cross-exclusion (a player picked on side 1 disappears from side 2's candidate list before either side is saved) works via `onAssignmentChange`/`excludePlayerIds` between the two live `SquadEditor` instances; only the "which squad id to save against" part relies on the save-triggered remount described above.
- Didn't add a delete affordance for a lineup squad from the Cancha editor (the publish/share/delete block is dream-only) — the task's Steps don't mention removing a saved lineup side, and re-saving a side just overwrites its slots anyway.
