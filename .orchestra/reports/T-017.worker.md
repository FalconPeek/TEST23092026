# T-017 worker report

## Summary
- `messages/es.ts`: added a new top-level `tournament: {...}` block (singular — mirrors the
  existing `match`/`matches` split: `tournaments` from T-016 is list-scoped, `tournament` is the
  hub/detail-scoped copy) with `openRegistration`, `closeAndGenerate`, `generateConfirm`,
  `generated`, `finish`, `register`, `unregister`, `registered(n)`, `entries`, `addEntry`,
  `entryName`, `seed`, `saveEntries`, `avgOvr`, `unassigned`, `needTwoEntries`, `tabs.*`, plus a
  few small additions needed for the editor UI: `entriesSaved` (save-success toast),
  `assignTo`/`removeEntry`/`removePlayer` (labels/aria-labels for the entries editor's controls).
- `lib/tournament/entries.ts` (+ `entries.test.ts`): pure helpers for the entries editor —
  `addEntry`/`removeEntry`/`renameEntry`/`setSeed`, `assignPlayer`/`unassignPlayer` (assigning
  always removes the player from every other entry first, so "≤1 team" holds by construction),
  `unassignedPlayerIds`, `averageOvr` (mirrors `lib/server/tournaments.ts`'s own averaging: empty
  roster / unknown player → default 60), and `validateEntries` (`too_few` / `empty_name` /
  `duplicate_seed` / `null`=valid).
- `components/tournament/entries-editor.tsx` (+ test): `'use client'`, teams-mode editor.
  Editable mode (admin, draft/registration): add/rename/remove entries, an optional seed input,
  a live avg-OVR readout per team, per-player unassign (×) buttons, and an "unassigned players"
  list where each player gets a `Select` to assign them onto a team. Validates with
  `validateEntries` before calling `saveTournamentEntries` (blocks with `needTwoEntries` for <2
  entries, the generic validation string otherwise) and toasts + `router.refresh()` on success.
  Non-editable mode (non-admin, or status past registration): read-only card list of teams and
  their rosters, no controls.
- `components/tournament/tournament-hub-client.tsx` (new, **not in the task's Files list** — see
  "Known issues" below): three small client pieces shared by the layout and the Resumen page —
  `TournamentTabs` (pathname-based active-tab highlighting, mirrors `BottomNav`'s pattern),
  `TournamentAdminControls` (status-driven buttons: draft → "Abrir inscripción"; draft/registration
  → "Generar fixture" behind a confirm dialog, disabled + a `needTwoEntries` hint when the entry
  count doesn't clear the bar; in_progress → "Terminar torneo"), and `TournamentRegisterButton`
  (individual mode self register/unregister).
- `app/g/[groupId]/torneos/[tournamentId]/layout.tsx` (new): loads the tournament (`notFound`
  if it doesn't belong to `groupId`), renders the header (name, status badge, format · entry
  mode · team size) and `TournamentTabs` — Llave shown for single_elim/double_elim/groups_ko,
  Tabla for league/groups_ko/swiss, Fechas once `in_progress`/`finished`.
- `app/g/[groupId]/torneos/[tournamentId]/page.tsx` (new, Resumen): branches on `entry_mode`.
  Individual mode: registration list + register/unregister button (hidden for spectators, and
  once the tournament leaves `registration`), "Generar fixture" gated on
  `registrations.length >= team_size * 2`. Teams mode: `EntriesEditor` (editable only while
  admin + draft/registration), "Generar fixture" gated on `>= 2` saved entries. Both branches
  show a short "fixture generated" summary + link to the Llave/Tabla tab once `in_progress` or
  `finished` (league links straight to Tabla since it has no bracket). No bracket/state is
  computed in the page itself — every mutation goes through `lib/actions/tournaments.ts`.

## Known issues / assumptions
- **Added `components/tournament/tournament-hub-client.tsx`, not listed in the task's Files
  section.** `layout.tsx` needs pathname-based active-tab highlighting and `page.tsx` needs three
  buttons wired to server actions (open registration / generate-with-confirm / finish / register
  self) — both are async Server Components, so that interactivity can't live in those files
  directly (a file is either `'use client'` or not). Rather than adding several more small
  unlisted files, I put all three pieces (`TournamentTabs`, `TournamentAdminControls`,
  `TournamentRegisterButton`) in one new client file, the same way T-016's
  `create-tournament-form.tsx` bundled its `TiebreakerEditor` sub-component inline. Flagging per
  the Worker protocol in case FATHER wants this split differently.
- The tab bar links to `/llave`, `/tabla`, `/fechas` (Spanish segments, matching the app's
  Spanish-path convention and `es.tournament.tabs.*`'s naming). None of those routes exist yet —
  they're T-018 (bracket) and T-019 (table/fixtures) — so following a tab from a tournament whose
  format/status makes it visible currently 404s. That's expected given the task order (T-018
  depends on T-017), not a regression.
- No dedicated "registration opened" / "tournament finished" toast strings were requested in the
  task's copy list, so `TournamentAdminControls` just refreshes the page for those two status
  changes (the status badge updating is the feedback); only "Generar fixture" has an explicit
  success toast (`es.tournament.generated`), an error toast, and a confirm dialog, matching what
  the task actually specified.
- Per T-016's verifier notes (carried over, not touched here): field-level zod error messages in
  `create-tournament-form.tsx` are still raw English zod text — flagged there for T-020 polish,
  unrelated to this task's files.
