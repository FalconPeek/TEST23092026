## Summary
- `messages/es.ts`: added `notificationsUi.*` (title, empty, markAllRead, unread(n), prefsTitle,
  `kinds.*` for all 9 notification kinds in the task's given order/wording, pushTitle/pushEnable/
  pushDisable/pushUnsupported/pushDenied/pushEnabled). Also added `notificationsUi.open` ("Ver"),
  a small necessary string for the realtime toast's "open this notification" action button, not
  explicitly named in the task's list.
- `lib/notifications/safe-url.ts` (+ test): `safeInternalUrl(url)` returns the normalized path
  (with query/hash preserved) for a genuine same-origin relative path, or `null` for anything else
  — protocol-relative (`//evil.com`), absolute (`https://…`), non-http schemes (`javascript:…`),
  or a path containing a control character/backslash a browser could normalize into an off-origin
  URL. Unlike `lib/supabase/env.ts`'s `safeNextPath` (which always needs *somewhere* to redirect
  to and falls back to `"/"`), this returns `null` on purpose so the caller can simply not render
  a link — matching the task's "starts with `/` and not `//`, else no link." 8 tests.
- `components/app-shell/notification-bell.tsx` (+ test, new): bell icon + unread badge (caps at
  "99+"). Subscribes once on mount to `postgres_changes` INSERT on `notifications` filtered to
  `user_id=eq.<me>`; each insert increments the count and shows a sonner toast (title/body from
  the payload, with an "Ver" action that navigates to the notification's `safeInternalUrl` when
  it has one). Unsubscribes (`removeChannel`) on unmount; the effect's only dependency is `userId`,
  so a re-render with the same user never opens a second channel. 6 tests, incl. one that
  explicitly re-renders and checks `channel()` was still only called once.
- `components/app-shell/top-bar.tsx`: loads the unread count (`head: true`, exact count) alongside
  the existing profile lookup, in the same `Promise.all`; renders `NotificationBell` next to the
  avatar menu; added a "Ajustes" (`/yo/ajustes`) item to that menu, per step 4's "link to it from
  the user menu."
- `app/notificaciones/page.tsx` (new): last 50 notifications, newest first, unread ones
  highlighted, relative time (`lib/format.ts`'s `formatRelative`). Each row goes through
  `safeInternalUrl` — a row with no safe url renders as a plain non-clickable container rather
  than a broken/dangerous link. Opening a (safe) row marks that one id read on click (fire-and-
  forget, doesn't block navigation); the top of the page has a "Marcar todas como leídas" button.
- `app/yo/ajustes/page.tsx` (new): reads `profiles.notification_prefs` (an absent key means
  enabled, per the Context — only `true`/`false` keys already present are passed through as
  `initialPrefs`, so `PrefsForm` itself decides the "missing = on" default) and renders
  `PrefsForm`. Linked from `/yo` (a small "Ajustes" link next to the dashboard title) and from the
  top bar's user menu.
- `components/notifications/prefs-form.tsx` (+ test, new): one `Switch` per notification kind,
  optimistic (flips immediately, calls `updateNotificationPrefs({prefs: {[kind]: checked}})` with
  just that one key — matching its "merge" semantics — and reverts + toasts on failure, without a
  disabled/pending state, since that's what "optimistic" means here). The push section reads
  `isPushSupported()`/`getPushPermission()` through `useSyncExternalStore` rather than
  `useEffect`+`setState` — this project's `react-hooks/set-state-in-effect` lint rule (correctly)
  flags synchronous `setState` in an effect body, and `useSyncExternalStore` is the React-native
  way to read a browser-only value without either an SSR/hydration mismatch or that lint error:
  `getServerSnapshot` keeps SSR consistent ("checking"), and React automatically re-renders once
  after hydration to reconcile with the real client value. Enabling/disabling push doesn't need
  its own local status state either — finishing their `useTransition` already triggers a
  re-render, which re-invokes the snapshot function and picks up the real (now-changed)
  `Notification.permission` on its own. 8 tests: toggle payload, revert-on-failure + error toast,
  default-all-on, a stored `false` respected, and all 4 push states (unsupported/denied/enabled/
  enable-then-becomes-enabled).
