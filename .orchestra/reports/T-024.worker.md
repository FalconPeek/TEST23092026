# T-024 worker report

## Summary
- `messages/es.ts`: added `rankings.*` — `title`, `metrics.*` (all 8), `impactoHelp`,
  `avgRatingHelp`, `empty`, `matchesPlayed(n)`, `you`.
- `lib/rankings/format.ts` (+ test): pure helpers.
  - `parseMetric(value)`: validates against the 8 known metrics, falling back to `"ovr"` for
    anything else (including `undefined`/`null`/an unknown string/an empty string) — this is the
    only thing standing between the raw `?metric=` query string and `get_group_leaderboard`'s
    `p_metric` param, which is typed as plain `text` server-side (no enum), so an invalid value
    truly can reach the RPC unvalidated if this doesn't catch it. Also handles the
    `string[]` case Next's `searchParams` type allows (repeated query param) by taking the first
    value.
  - `formatMetricValue(metric, value)`: one decimal for `avg_rating`, rounded integer otherwise.
  - `splitPodium(rows)`: groups rows into up to 3 `PodiumPosition`s (rank 1/2/3, ascending) plus a
    flat `rest` array for rank 4+. A `PodiumPosition` holds a `rows` array rather than a single
    row specifically to handle ties — e.g. two players tied at rank 1 both land in
    `positions[0].rows`, and a 3-way tie at rank 3 puts all three in `positions[2].rows` — so the
    UI never has to assume "exactly 3 people on the podium." Tests cover a clean 1-2-3, a tie at
    1st, a 3-way tie at 3rd, and the empty case.
- `components/rankings/podium.tsx` (+ test): server-safe. Renders `positions[0]` (1st, possibly
  several tied players) larger and in the middle, flanked by `positions[1]`/`positions[2]`
  (2nd/3rd) smaller — each slot renders every tied player in it, not just one. My own row shows
  "Vos" instead of my name and gets a ring highlight. Each player links to their profile. Tests:
  empty podium renders nothing, a clean top-3 all link correctly, a 2-way tie at 1st renders both
  players, "Vos" replaces my name, `avg_rating` shows one decimal.
- `components/rankings/leaderboard-list.tsx` (new, no test per the task's Files list): server-safe
  list for rank 4+ — rank number, avatar, name (or "Vos" + highlight for my row), muted
  `matchesPlayed(n)` sub-line, and the formatted value. Renders nothing for an empty list (the
  page's own `rankings.empty` message covers the fully-empty-leaderboard case; this only covers
  "podium took everyone").
- `app/g/[groupId]/rankings/page.tsx` replaces the T-006 placeholder:
  - `searchParams.metric` → `parseMetric` → the validated `Metric`, before it's ever handed to
    `supabase.rpc("get_group_leaderboard", ...)`.
  - A horizontally-scrollable metric chip bar (`-mx-4 ... overflow-x-auto`, so only the chip row
    scrolls, never the page), each chip a `?metric=` link, ≥44px tall, active one highlighted.
  - `Podium` for positions 1-3, `LeaderboardList` for the rest, `rankings.empty` when the RPC
    returns no rows at all.
  - `impactoHelp`/`avgRatingHelp` shown only for their respective metric.
  - A non-member's RPC call fails with `PICADO_NOT_MEMBER` (the RPC's own enforcement — no
    separate membership pre-check needed, matching the task's "no client fetching is needed" /
    read-via-session-client framing); that error path calls `notFound()`.
  - My own player id (for the "Vos" highlight) comes from a plain `players` lookup by
    `(group_id, user_id)`, excluding `left_at`, run in parallel with the RPC call.
