    the task's exact names and the given parenthetical hints as descriptions where provided, and a
    short analogous Spanish sentence where it wasn't (e.g. `first_match`: "Jugaste tu primer
    partido.").
  - `profile.share`/`profile.downloadCard`/`profile.shareText`.
- `lib/notifications/templates.ts` (+ test): deleted `FALLBACK_STRINGS`, `StringsTable`,
  `isStringsTable`, and `stringsFor` entirely; every builder now calls `es.notifications.<kind>`
  directly (real typed function calls, not the old `unknown`-typed runtime shape check).
  `badgeAwardedPayload` keeps its exact signature (`{badgeCode, url}`) — **no caller changes were
  needed** — but internally resolves `es.badges[badgeCode]?.name` and passes that as `badgeName`
  to `es.notifications.badge_awarded`, falling back to the raw code only if it's ever an unknown
  one (defensive; never happens with the current 15-code catalog). Updated the test's badge
  assertion to check the Spanish name appears and the raw code doesn't; removed the file's
  "exercises FALLBACK_STRINGS today" comment since that's no longer true.
- `components/player/badge-list.tsx` (+ test, new): server-safe. Maps the DB's `icon` string
  (`whistle`, `shirt`, `ball`, `hat-trick`, `boot`, `star`, `shield`, `flame`, `trophy`, `eye`,
  `card-gold` — read directly from the `badges` seed migration, not guessed) to a lucide
  component (`Goal` for "ball", `Sparkles` for "hat-trick", `Footprints` for "boot" — lucide has
  no literal "Boot" — `CreditCard` for "card-gold", the rest map 1:1), falling back to `Award` for
  anything unrecognized. Shows name + description (as a visible sub-line *and* a `title` tooltip,
  covering the task's "tooltip/sub-line" either way) and a `×n` badge only when `count > 1`. Empty
  state is `badges.none`. Tests: empty state, name+description shown, ×n shown/hidden, unknown-icon
  fallback renders *some* icon.
- `components/player/share-card-button.tsx` (+ test, new): `'use client'`. Fetches
  `/api/og/card/[playerId]` as a Blob, wraps it in a `File` (`carta-<slugified-name>.png`), and
  tries `navigator.canShare?.({files:[file]})` → file share, else `navigator.share` → URL share,
  else `navigator.clipboard.writeText(url)` + `profile.linkCopied` toast. Catches and silently
  ignores `AbortError` (cancelled share sheet); any other error toasts the generic error copy.
  Also renders a `download`-attributed link to the same route. Absolute URL built from
  `window.location.origin` rather than importing a server-leaning `siteUrl()` helper into a client
  bundle. Tests: file-share path, URL-share fallback, clipboard fallback, AbortError swallowed,
  download link attributes. The clipboard test needed `vi.spyOn(navigator.clipboard, "writeText")`
  rather than replacing `navigator.clipboard` wholesale — this jsdom version implements a real
  Clipboard API, so `Object.defineProperty(navigator, "clipboard", {value: ...})` silently didn't
  shadow it the way the same trick works for `share`/`canShare` (which jsdom doesn't implement).
- `app/g/[groupId]/jugadores/[playerId]/page.tsx`: added a `player_badges` query joined with
  `badges(icon, sort)` via the existing FK embed, sorted by `badges.sort` client-side (Postgres
  embeds don't order by a joined table's column directly), mapped to `BadgeList`'s `EarnedBadge[]`
  shape, and rendered under a new "Insignias" (`badges.title`) section. `ShareCardButton` renders
  under the card (only when `cardProps` exists — sharing a card that hasn't rendered yet doesn't
  make sense), next to the existing vote/edit buttons.
