# T-032 worker report

## What changed

- `messages/es.ts`: added `tournament.useClub` ("Usar club") and `tournament.noClub` ("Sin club").
- `lib/tournament/entries.ts` (+ tests): added `clubId: string | null` to `DraftEntry` (`addEntry` defaults it to `null`) and a new pure helper `setEntryClub(entries, entryId, club | null)` — picking a club renames the entry to the club's name and replaces its roster with the club's players minus whoever is already on another entry; passing `null` only clears `clubId`, leaving name/players untouched. 4 new tests.
- `components/tournament/entries-editor.tsx` (+ test): new optional `clubs?: EntryClub[]` prop (club id/name/colors/crest + roster `playerIds`). Each entry (both editable and read-only views) shows a small `ClubCrest` next to its name when it has a club. In edit mode, a club `Select` per entry (rendered only when `clubs.length > 0`, so existing tests without a `clubs` prop are unaffected) calls `setEntryClub` on pick/clear. The save payload now includes `clubId` per entry. 3 new tests (prefill on pick, roster players already used elsewhere are skipped, payload carries `clubId`).
- `components/tournament/standings-table.tsx` (+ test): `StandingsRowDisplay` gained `clubId: string | null`; new optional `clubsById?: Map<string, StandingsClub>` prop (keyed by **club id**, per the task) renders a crest before the entry name when the row's club resolves. 2 new tests.
- `components/tournament/bracket-view.tsx`: new optional `clubsByEntry?: Map<string, BracketClub>` prop, threaded through `MatchCard`/`SlotRow`. **Deviation from the literal "clubsById" naming**: `lib/tournament/bracket-layout.ts` (not in this task's Files list, so left untouched) already gives each `BracketSlotDisplay` an `entryId`, but never a `clubId` — so the map here is keyed by **entry id** instead, resolved once per page from a club-id-keyed lookup joined against the entries' `club_id`. Same visual result, just named `clubsByEntry` to be honest about the key. No test file existed for this component before and none was requested.
- `components/tournament/fixtures-list.tsx` (+ its existing test file, mechanically updated): `FixtureEntryInfo` gained `clubId: string | null` (it's this component's own type, so no bracket-layout-style workaround needed here); `resolveSide`/`EntrySide` carry it through; new optional `clubsById?: Map<string, FixtureClub>` (keyed by club id) renders a crest per side via a small `EntryNameRow` helper.
- Pages — each now runs one extra `clubs` query for the group and builds the map the corresponding component needs, following the existing per-page query style (no new shared helper module, consistent with this codebase's preference for small duplication over premature abstraction):
  - `app/g/[groupId]/torneos/[tournamentId]/page.tsx`: entries now select `club_id`; clubs query includes `club_players(player_id)` for the roster prefill; passes `clubs` to `EntriesEditor`.
  - `.../tabla/page.tsx`: entries query gains `club_id`, rows get `clubId`, passes `clubsById` (by club id) to `StandingsTable`.
  - `.../llave/page.tsx`: entries query gains `club_id`; builds `clubsByEntry` (entry id → club) and passes it to `BracketView`.
  - `.../fechas/page.tsx`: entries query gains `club_id`, passes `clubsById` (by club id) to `FixturesList`.
