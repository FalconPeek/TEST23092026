# T-028 worker report

## Summary
Fixed the rejected T-018 bug: the champion was being declared from GF1's result alone, even
when a grand-final reset (GF2) was still pending after the losers-bracket team won GF1.

- `lib/tournament/bracket-layout.ts`: replaced the champion computation (previously "highest-round
  *completed* `final`-bracket match") with a new `resolveChampion(finalMatches)` helper that looks
  at the **last** `final`-bracket match by round:
  - `completed` → that match's `winnerEntryId` is champion (covers single_elim/groups_ko's lone
    final, and double_elim's GF2 once the reset is actually played).
  - `archived` → the reset wasn't needed (the winners-bracket team won GF1 outright); champion is
    the previous match's (GF1's) winner if it's `completed`.
  - anything else (`locked`/`waiting`/`ready`/`in_progress`) → `null` — this is the fix: GF2
    sitting `ready` after LB won GF1 no longer falls through to GF1's winner.
  - No final matches at all → `null`.
- `app/g/[groupId]/torneos/[tournamentId]/llave/page.tsx`: added `status` to the tournament
  select and gated `championName` on `tournament.status === "finished"` as well as
  `layout.championEntryId`, so the banner never renders before the organizer has actually closed
  the tournament out, even in some edge case the layout module didn't anticipate.
- `lib/tournament/bracket-layout.test.ts`: added a new `"buildBracketLayout: champion resolution"`
  describe block with the four cases T-028 asked for, built against the real
  `generateDoubleElim`/`generateSingleElim` engines + `applyResult` (not hand-rolled fixtures):
  1. LB wins GF1, GF2 `ready` → `championEntryId` is `null`.
  2. GF2 `completed` → champion is GF2's winner.
  3. WB wins GF1 outright (GF2 `archived`) → champion is GF1's winner.
  4. single_elim with the final still `ready` → `null`.
  The original DE-reset test (GF2 completed → champion from GF2) is unchanged and still passes,
  since that branch of the new logic is equivalent to the old one; only the "GF2 pending" and
  "GF2 archived" branches were new/changed behavior.
