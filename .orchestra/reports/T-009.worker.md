# T-009 worker report

## Summary
Added the group settings form (bound to `groupSettingsSchema`, with an auto-generated
"Avanzado" section over every remaining numeric `rating.*` field) at the top of
`/g/[groupId]/ajustes` for admins, and a player profile editor at
`/g/[groupId]/jugadores/[playerId]/editar` with a "Editar mi perfil" link from the group
home's member preview.

## Files changed
- `messages/es.ts` — added `groupSettings.*` (every label/help text the task listed) and
  `player.*` (`displayName`, `primaryPosition`, `altPositions`, `altPositionsHint`,
  `preferredFoot`, `heightCm`, `save`, `editMyProfile`).
- `components/settings/group-settings-form.tsx` (new) — client form holding the full
  `GroupSettings` object in state (via generic `setIn`/`getIn` path helpers, since the
  schema is deeply nested and has no arrays). Common fields: name, `default_team_size`
  (select 5/6/7/8/9/11), `windows.report_hours`/`rating_hours`, `rating.spectator_weight`,
  `rating.min_raters`, `tiers.silver_min/gold_min/special_min`,
  `tiers.special_on_last_match_mvp`, `scouting.revote_days`,
  `scouting.require_shared_match`, `spectators_can_rate`, `badges_enabled` — exactly the
  task's list (I deliberately left out `scouting.allow_detailed_mode` and the whole
  `playstyles.*` group: neither is in the task's explicit common-field list nor under
  `rating.*`, so surfacing them would be unrequested scope). The `<details>/<summary>`
  "Avanzado" section walks `settings.rating` recursively (`collectNumericFields`), skipping
  the two paths already shown as common fields (`rating.spectator_weight`,
  `rating.min_raters`), humanizing each remaining leaf's key as the label — this covers
  `form.*`, `rate_limit.*`, `openskill.*` and the rest of the top-level `rating.*` scalars
  automatically, so a newly added numeric tunable in the schema needs no UI change.
  Validates with `groupSettingsSchema.safeParse` before ever calling `updateGroup`;
  per-field errors are keyed by the issue's dotted path, with two fallback slots
  (`errors.tiers`, `errors.rating`) for the schema's two object-level `.refine()`s (tier
  ordering, reliability min≤max), whose zod issue path has no matching leaf input.
  "Restaurar valores por defecto" resets to `defaultGroupSettings` (name is untouched by
  reset — only settings are described as resettable in the task).
- `components/settings/group-settings-form.test.tsx` (new) — renders defaults; an
  out-of-range value (`report_hours = 0`) blocks the submit and shows an error; reset
  restores defaults after a field was changed; a valid edit calls `updateGroup` with the
  parsed settings.
- `app/g/[groupId]/ajustes/page.tsx` — added the `Configuración del grupo` section
  (admin-only; fetches `groups.name/settings` only when `admin`, parses with
  `parseGroupSettings`, hidden entirely for non-admins per the task — no read-only summary).
- `app/g/[groupId]/jugadores/[playerId]/editar/page.tsx` (new) — loads the target `players`
  row and the caller's `group_members` role in parallel; `notFound()` if the player doesn't
  belong to this group or has left; `editedByAdmin` is true only when the target is an
  **unclaimed guest** (`is_guest`, since a claimed one has `is_guest = false`) and the
  caller is owner/admin; `notFound()` for every other non-self case (editing someone else's
  linked profile, or a non-admin trying to edit any guest).
- `components/player/player-profile-form.tsx` (new) — name, primary position (`Select`
  over `POSITIONS`/`es.positions`, "Sin definir" option), alternate positions as toggle
  chips capped at 4 and excluding whatever's currently selected as primary (chosen
  primary is filtered out of the alt-chip list entirely, and picking a new primary drops
  it from the alt selection if it was there), preferred foot (`RadioGroup`), height.
  Submits to `updateMyPlayer` normally, or `updatePlayer({ ...input, playerId })` when
  `editedByAdmin`.
- `components/player/player-profile-form.test.tsx` (new) — alt-chip cap at 4 + primary
  exclusion (2 tests), and that the right action (`updateMyPlayer` vs `updatePlayer`) is
  called depending on `editedByAdmin`. Radix `Select`'s pointer-based interactions need
  `hasPointerCapture`/`releasePointerCapture`/`scrollIntoView`, which jsdom doesn't
  implement; added a local `beforeAll` polyfill in this test file only, since
  `vitest.setup.ts` isn't in this task's **Files** list (noting it here rather than editing
  it — worth promoting to the shared setup file the next time any test needs to interact
  with a Radix `Select`, since this is the first one that did).
- `app/g/[groupId]/page.tsx` — added an "Editar mi perfil" button next to the member-count
  line, shown only when the signed-in user has their own `players` row in this group
  (naturally absent for spectators, who don't get one on join — matches `accept_invite`).
