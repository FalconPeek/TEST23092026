# T-030 worker report

## What changed

- `messages/es.ts`: filled out the `squads` namespace (kept `ratingShort`/`chemistryShort`) with all keys from the task spec, plus a few small additions needed by the UI: `empty`, `emptyCommunity`, `club`, `noClub`, `remove`. Also added `profile.buildSquad` ("Armá tu plantilla") for the profile-page entry link.
- `lib/squads/editor-state.ts` (+ test, 10 cases): pure UI-state helpers separate from the engine's `SquadAssignment` — the editor only needs slot→playerId while the user edits, and looks the rest up from the loaded context.
  - `setSlot`/`clearSlot`: place/remove a player, `setSlot` moves a player instead of duplicating them if they were in another slot.
  - `changeFormation`: drops slots that don't exist in the new formation, keeps the rest (same-size formations never drop anyone since every formation for a team size has the same slot-index range).
  - `candidatesForSlot`: group players not already placed anywhere, sorted by OVR at the requested position, tagged `primary`/`alt`/`other` fit.
- `components/squads/pitch.tsx`: server-safe presentational pitch (no `'use client'`) — slot markers positioned from the formation's x/y%, tier-gradient mini cards (duplicated tier-class map from `player-card.tsx`, same pattern as other small per-file duplicated helpers in this codebase), chemistry dots (capped display at 3), empty slots show "+". Takes an optional `onSlotClick`; only becomes interactive when rendered inside a client component's tree (the editor), read-only pages pass no handler.
- `components/squads/squad-editor.tsx` (+ test, 3 cases): the `'use client'` all-in-one owner UI — name, team size select, formation chips, the interactive pitch, live rating/chemistry (via `buildSquadView` from `lib/squads`, so the numbers are always engine-derived, matching the acceptance criterion), club select with crest preview, Save (create or update via `saveSquad`), and — once the squad has an id — Publish/Unpublish, Share (Web Share API with the `/api/og/squad/[id]` PNG as a file when possible, else URL, else clipboard — same pattern as `share-card-button.tsx`, inlined here since that pattern isn't extracted into a shared helper), and Delete-with-confirm. The bottom sheet (shadcn `Sheet`, `side="bottom"`) lists candidates for a tapped slot with a "Quitar" option when the slot is filled.
- `app/g/[groupId]/plantillas/page.tsx`: "Equipo de la semana" (via RPC `get_featured_squad`, mini pitch), "Mis plantillas" (list with rating/chemistry/published badge), "Del grupo" (published squads by others with a like toggle and count), "Nueva plantilla" button (shown to any member with a player row — creation isn't admin-gated, `RLS`/the `save_squad` RPC own the actual authorization).
- `app/g/[groupId]/plantillas/nueva/page.tsx` and `app/g/[groupId]/plantillas/[squadId]/page.tsx`: the detail route branches on `owner_player_id === myPlayerId` — owner gets `SquadEditor` (which itself handles publish/delete/share); everyone else gets a read-only `Pitch` + `LikeButton`, 404s on an unpublished squad or a non-`dream` (lineup) squad.
- `app/g/[groupId]/page.tsx` and `app/g/[groupId]/jugadores/[playerId]/page.tsx`: added the "Plantillas" entry link on group home and "Armá tu plantilla" on the player's own profile — no other changes to either file.

## Notes for Verifier

- `buildSquadView` needs `{ team_size, formation, slots: [{slot, player_id}] }`; the raw DB rows have `squad_slots` (the embedded relation name), so every call site remaps it (a tiny `squadViewInput` helper in the list page, inline in the detail page and the editor).
- The editor reuses `buildSquadView` for its own live preview instead of recomputing rating/chemistry by hand — this was a deliberate simplification once I realized the assignment-as-stored-slots shape and the engine's own view builder line up exactly; it also means the editor, the list pages, and the OG share image are all guaranteed to agree on rating/chemistry (same acceptance criterion).
- Squad creation is not admin-gated in the list page (unlike clubs) — nothing in the task or the backend RPCs suggested "Mis plantillas" should be admin-only, and `save_squad`'s own authorization (via `owner_player_id`) is what actually decides who can write.
