# T-019 worker report

## Summary
- `messages/es.ts`: added `standings.*` — column abbreviations with `*Title` tooltip strings
  (Pos, PJ, G, E, P, GF, GC, DG, Pts, Buch., S-B), `qualified`, `group(label)`, `matchday(n)`,
  `swissRound(n)`, `noMatches`, plus a small `lot` string (tooltip text for the "decided by draw"
  marker — not explicitly named in the task's copy list but needed for the marker's `title`).
- `components/tournament/standings-table.tsx` (+ test): server-safe. Renders `StandingsRowDisplay[]`
  (already fully computed by the caller — no math happens here) as a compact table: Pos/name/PJ/DG/Pts
  always visible, G/E/P/GF/GC and (when `showSwissColumns`) Buch./S-B behind `sm:table-cell`. A
  qualifying row (`row.qualifies`) gets a left accent border; a `*` with a `title` tooltip marks a
  position `lot`-decided. Uses the existing `Table` primitive, whose own container already
  scrolls horizontally on its own (never the page). Tests: empty state, qualifying highlight
  present/absent, swiss-only columns shown/hidden, lot marker shown/hidden, group-label heading.
- `components/tournament/fixtures-list.tsx` (+ test): server-safe. Groups `FixtureMatch[]` into
  sections: groups_ko group-stage matches by *group label then round* (`"Grupo A · Fecha 1"`),
  plain league matches (bracket `group`, no group label) by matchday, swiss matches by round —
  the three cases the task names. Pure single_elim/double_elim (and a groups_ko KO stage) have no
  matchday/round concept, so their `winners`/`losers`/`final`/`third` matches fall back to one
  section per bracket type (in play order) instead of being dropped or showing a misleading "no
  matches" — `llave` already visualizes those properly, this is just enough that the "Fechas" tab
  (shown for every format once `in_progress`, per T-017's layout) doesn't look broken for
  single_elim/double_elim. Each row resolves bye/tbd/entry-name the same way
  `lib/tournament/bracket-layout.ts` does (kept as a small local `resolveSide` here rather than
  importing/exporting that module's private helper, per CLAUDE.md's "three similar lines" over a
  premature shared abstraction — it's ~6 lines), shows the score or a status chip, a link to the
  real match, and (admin) reuses T-018's `MatchAdminMenu` unchanged. Tests: matchday grouping,
  group+matchday grouping, swiss-round grouping, the KO fallback section, the empty state, and a
  bye row rendering "Libre" instead of a resolved name.
- `app/g/[groupId]/torneos/[tournamentId]/tabla/page.tsx` (new): `notFound()`s for
  single_elim/double_elim (no table). Calls
  `computeStandings(createSupabaseTournamentRepo(sessionClient), tournamentId, rng)` exactly as
  the Context snippet shows, maps each `StageStandings` to `StandingsRowDisplay[]` (entry names
  from `tournament_entries`, group labels from `stage_groups` joined by `computeStandings`'
  `groupId`, which is the *engine key*, not the `stage_groups.id` uuid — confirmed by reading
  `tournament-repo.ts`'s `loadState`, which sets `Group.id = engine_key`), and marks a row
  `qualifies` when the format is `groups_ko` and its rank is within
  `settings.groups_ko.qualifiers_per_group`. The `rng` passed to `computeStandings` is seeded
  deterministically from the tournament id (a tiny local string hash), not `Date.now()`, so a
  "lots" tiebreak (only reachable on an exact multi-way tie) renders the same way on every
  refresh instead of reshuffling per request — `computeStandings` recomputes on every read since
  standings aren't persisted, so an unseeded RNG would otherwise flicker.
- `app/g/[groupId]/torneos/[tournamentId]/fechas/page.tsx` (new): session-client reads of every
  `tournament_matches`/`tournament_entries`/`stage_groups` row for the tournament (no format
  gating — every format gets a Fechas tab per T-017), maps DB rows to `FixtureMatch[]` and
  renders `FixturesList` + `TournamentRealtime`.
