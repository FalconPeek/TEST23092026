- `lib/tournament/bracket-layout.ts` (+ test): pure `buildBracketLayout(matches, entries)`.
  Groups `tournament_matches` rows into sections by `bracket` (`group`/`swiss` rows are filtered
  out — the standings table handles those). Key subtlety, verified against `lib/brackets`'
  actual generators: `single_elim`/`groups_ko`'s KO stage relabel the ladder's very last round
  from `winners` to `final` (continuing the same round numbering), so the `winners` section's
  round-label totals merge in that trailing `final` round when its round number is contiguous
  with the winners bracket's own max round -- otherwise (double_elim, whose grand-final restarts
  its own round numbering at 1) they're computed independently. This makes `round()` correctly
  read "Cuartos de final"/"Semifinal"/"Final" across a merged single_elim ladder, while double_elim
  gets a real "Llave principal" vs. "Llave de perdedores" vs. "Final" (Gran final/Final de
  desempate) split. Entry slots resolve to entry name / `Libre` (bye) / `A definir` (tbd) /
  `{rank}º Grupo {label}` (groups_ko qualifier placeholder), and the champion is the winner of the
  highest-round *completed* `final`-bracket match (naturally picks GF2 over GF1 once a reset was
  played, and falls out to `null` before the final is decided) -- nothing here is computed by any
  UI component. Tests use the real `generateSingleElim`/`generateDoubleElim` engines (not
  hand-rolled fixtures) as inputs, covering: SE-8 with byes (round labels, bye/tbd slots), SE-4
  with a third-place match, and DE-4 forced through a grand-final reset (GF1/GF2 labels + champion
  comes from GF2).
- `components/tournament/bracket-view.tsx` (server-safe, no `'use client'`): renders each section
  as its own horizontally-scrollable (snap-x, `-mx-4 px-4` viewport bleed so only this container
  scrolls, never the page) row of round columns; each match card shows both slots (name + score,
  winner bold, bye dimmed), a status chip (`bracket.matchStatus`), pens/walkover footnotes, a link
  to the real match once `matchId` is set, and (when `admin`) composes the client
  `MatchAdminMenu` leaf per match — a Server Component can render a Client Component child, so
  the file itself stays hook-free.
- `components/tournament/match-admin-menu.tsx` (+ test): `'use client'`, admin-only, renders
  nothing when neither playing/entering/editing applies. "Programar partido" (only when `ready`
  and no `matchId` yet) opens a datetime+venue dialog → `startTournamentMatch` → navigates to the
  new match's lineup page. "Cargar resultado"/"Corregir resultado" open a shared result dialog:
  score steppers, a pens toggle+steppers that only appears once the two scores are tied (verified
  against `tm_apply_result`'s SQL: a tied KO match needs either pens or a manual/walkover
  winner, else `PICADO_KO_DRAW`), and a walkover switch that swaps the steppers for a winner
  `Select` built from the two already-resolved slot names — submitting without picking a winner
  is blocked client-side. Submits `confirmTournamentResult`/`editTournamentResult` accordingly.
- `components/tournament/tournament-realtime.tsx`: subscribes to `tournament_matches`
  (`tournament_id=eq.<id>`) and `tournaments` (`id=eq.<id>`) `postgres_changes`, debounces
  `router.refresh()` by 500 ms, unsubscribes on unmount. Renders nothing.
- `app/g/[groupId]/torneos/[tournamentId]/llave/page.tsx` (new): session client loads the

## Known issues / assumptions
- Per the Context note that `matches` is also in the realtime publication: I did **not**
  subscribe to it from `TournamentRealtime`. `matches` has no `tournament_id` column (only a
  per-row `tournament_match_id`), so there's no single equality filter that means "this
  tournament's matches"; and the finalizer already writes the outcome back into the corresponding
  `tournament_matches` row when a linked real match finalizes, so subscribing to
  `tournament_matches` alone already surfaces that change on this page. Documented this reasoning
  in the component's own comment; flagging here in case a `matches` subscription is wanted for a
  different reason I'm not seeing (e.g. live score while a real match is still `reporting`,
  which this bracket view doesn't display anyway).
- Manually verified live (no local Supabase stack running in this session, matching the pattern
  noted in prior worker reports): could not do the two-tab realtime smoke test end-to-end. The
  subscription code mirrors the exact API shape Supabase's `postgres_changes` expects and the
  existing `lib/supabase/client.ts` browser client; recommend a live check once the stack is up.
- `es.bracket.round`'s "Cuartos de final"/"Octavos de final" naming only makes sense from
  distance 2/3 onward; for tournaments too small to reach those distances (e.g. a 4-entry
  bracket only ever has distances 0/1) it never comes up, so it wasn't specifically tested beyond
  the 8-entry case already covering distance 2.
