## Context
M7 "Plantillas" (user request): groups get predefined teams ("clubes") with a name, 2–4 letter short name, primary/secondary colors, an uploaded crest, and a roster. Backend (committed):
- **Tables:** `clubs(id, group_id, name, short_name, primary_color, secondary_color, crest_path, created_at)` and `club_players(club_id, player_id, shirt_number)`. Members can read them.
- **Actions** (`lib/actions/clubs.ts`, admin-only via RPC): `createClub({ groupId, name, shortName, primaryColor, secondaryColor }) → { clubId }`, `updateClub({ groupId, clubId, name, shortName, primaryColor, secondaryColor, crestPath: string|null })`, `deleteClub`, `setClubPlayers({ groupId, clubId, players: [{ playerId, shirtNumber|null }] })`.
- **Crest upload** happens in the browser, straight to Supabase Storage bucket `club-crests` at path `<groupId>/<clubId>.<ext>`:
  - ext is png, jpg, jpeg or webp; max 512 KB; SVG is rejected on purpose.
  - Storage RLS lets only that group's admins write there.
  - Use `createClient()` from `lib/supabase/client.ts`: `storage.from("club-crests").upload(path, file, { upsert: true, contentType })`, then call `updateClub({ ..., crestPath: path })`.
  - Public URL: `storage.from("club-crests").getPublicUrl(path)`. Add a cache-busting `?v=<updated timestamp or Date.now()>` after upload.

## Steps
1. `messages/es.ts`: extend the existing `squads` namespace (FATHER added `ratingShort`/`chemistryShort`; keep them) or add a `clubs` namespace:
   - `title` "Clubes", `new` "Nuevo club", `empty` "Todavía no hay clubes.", `name` "Nombre", `shortName` "Abreviatura (2 a 4 letras)", `primaryColor` "Color principal", `secondaryColor` "Color secundario";
   - `crest` "Escudo", `uploadCrest` "Subir escudo", `removeCrest` "Quitar escudo", `crestHelp` "PNG, JPG o WebP de hasta 512 KB.", `crestTooBig` "El escudo pesa más de 512 KB.", `crestBadType` "Formato no permitido. Usá PNG, JPG o WebP.";
   - `roster` "Plantel", `shirtNumber` "Número", `saved` "Club guardado", `deleted` "Club eliminado", `deleteConfirm`.
2. `components/clubs/club-crest.tsx` (server-safe): the crest image when `crest_path` is set, otherwise a shield (reuse the card clip-path style) filled with the primary color and the short name in the secondary color. Sizes sm/md/lg; `alt` = club name.
3. `app/g/[groupId]/clubes/page.tsx`: a grid of clubs (crest, name, roster count). Admins get a "Nuevo club" button.
4. `app/g/[groupId]/clubes/[clubId]/page.tsx` + `components/clubs/club-form.tsx` (`'use client'`):
   - Admins: edit name/short name, two `<input type="color">` with a live crest preview, crest upload (validate type and size client-side before uploading, then show the preview), remove crest, delete club (confirm).
   - Roster editor: pick group players (checkbox list) with optional shirt numbers (unique 1–99) → `setClubPlayers`.
   - Non-admins see a read-only club page (crest, colors, roster with shirt numbers and card OVR).
   - All controls ≥44px.
5. Entry points: a "Clubes" link on the group home and in `/g/[groupId]/ajustes`.
6. Tests: `components/clubs/club-crest.test.tsx` (image vs fallback shield), and `components/clubs/club-form.test.tsx` (rejects >512 KB and SVG before any upload; unique shirt numbers; submit payloads; mock the actions and the supabase browser client).
