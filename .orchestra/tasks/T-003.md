## Context
Auth is Supabase (`@supabase/ssr`). Already written: `lib/supabase/server.ts` (`createClient()`, `getUserId()`), `lib/supabase/env.ts` (`siteUrl()` returns the site URL **with trailing slash**, `safeNextPath(next)` open-redirect guard returning a safe relative path), `app/auth/callback/route.ts` (PKCE code exchange → redirects to `next`, or to `/auth/auth-code-error` on failure), `proxy.ts` (redirects unauthenticated users on private paths to `/login?next=<path>`). Dev uses the **local** Supabase stack; magic-link emails arrive in Mailpit (http://127.0.0.1:54324). Email+password is used for dev/e2e test users. OAuth providers: Google and Discord (credentials come later; buttons must exist now and gracefully show the error toast if the provider is not configured).

Server Action rules (CLAUDE.md "Security rules"): zod-parse input → call Supabase → return typed `{ ok: true, data } | { ok: false, error }`; never throw raw errors to the client; error messages come from `messages/es.ts`. Read the Next 16 docs in `node_modules/next/dist/docs/` for Server Actions / `redirect` / `useActionState` before writing.

## Steps
1. `lib/actions/result.ts`: export `type ActionResult<T = void> = { ok: true; data: T } | { ok: false; error: string }` and helpers `ok(data)`, `fail(error)`. (Shared by all future actions.)
2. `lib/actions/auth.ts` (`'use server'`), named exports:
   - `signInWithOAuth(provider: "google" | "discord", next?: string)`: zod-validate; `supabase.auth.signInWithOAuth({ provider, options: { redirectTo: \`${siteUrl()}auth/callback?next=${encodeURIComponent(safeNextPath(next))}\` } })`; on success `redirect(data.url)`; on error return `fail(es.common.error)`.
   - `sendMagicLink(prevState, formData)` (for `useActionState`): fields `email`, `next`; zod email → on invalid return `fail(es.auth.invalidEmail)`; `signInWithOtp({ email, options: { emailRedirectTo: <same callback URL>, shouldCreateUser: true } })`; return `ok(undefined)` so the UI shows `es.auth.magicLinkSent`.
   - `signInWithPassword(prevState, formData)`: fields `email`, `password` (min 6), `next`; on error return `fail(es.auth.invalidCredentials)`; on success `redirect(safeNextPath(next))`.
   - `signOut()`: `supabase.auth.signOut()` then `redirect("/login")`.
3. `app/login/page.tsx` (Server Component; `searchParams` is async in Next 16): if the user is already signed in (`getUserId()`), `redirect(safeNextPath(next))`. Otherwise render the login card: app name/title, Google button, Discord button, separator `es.auth.orEmail`, then shadcn `Tabs` with "Link mágico" (email form) and "Contraseña" (email + password form). Pass `next` through hidden inputs / arguments.
4. `components/auth/login-form.tsx` (`'use client'`): the interactive parts (OAuth buttons calling the action, the two forms with `useActionState`, pending states on buttons, inline error text, success message after magic link sent). Use lucide icons if helpful; no brand SVG libraries.
5. `app/auth/auth-code-error/page.tsx`: simple centered message (`es.auth.codeErrorTitle`, `es.auth.codeErrorBody`) and a button linking to `/login`.
6. `components/auth/login-form.test.tsx`: Testing Library test that the form renders both tabs and the OAuth buttons, and that submitting an invalid email shows `es.auth.invalidEmail` (mock `@/lib/actions/auth` with `vi.mock`).
