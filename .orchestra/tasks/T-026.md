## Context
- **`notifications`:** `(id, user_id, group_id, kind, payload {title, body, url}, created_at, read_at)`. Users read only their own rows, and the table is in the realtime publication.
- **Actions** (`lib/actions/engagement.ts`): `markNotificationsRead({ ids? })` (omit ids = all), `updateNotificationPrefs({ prefs: Record<kind, boolean> })` (merges), `savePushSubscription` / `deletePushSubscription`.
- **Prefs:** stored in `profiles.notification_prefs` (an absent key means enabled).
- **Push client helper:** `lib/push/client.ts` (built by FATHER): `isPushSupported()`, `getPushPermission()`, `subscribeToPush()`, `unsubscribeFromPush()`. If it doesn't exist yet, set this task back to `todo`, note that in your report, and stop.
- **Notification kinds:** `NOTIFICATION_KINDS` in `lib/notifications/templates.ts`.

## Steps
1. `messages/es.ts`: add `notificationsUi.*`:
   - `title` "Notificaciones", `empty` "No tenés notificaciones.", `markAllRead` "Marcar todas como leídas", `unread` `(n) => …`;
   - `prefsTitle` "Qué te avisamos", one short label per kind (match_scheduled "Partido programado", report_pending "Cargar resultado", rating_pending "Votar partido", match_finalized "Partido finalizado", match_disputed "Partido en disputa", tournament_generated "Fixture de torneo", tournament_match_ready "Partido de torneo listo", badge_awarded "Insignias", card_updated "Cambios en mi carta");
   - `pushTitle` "Notificaciones en el celular", `pushEnable` "Activar", `pushDisable` "Desactivar", `pushUnsupported` "Tu navegador no soporta notificaciones push. En iPhone, agregá Picado a la pantalla de inicio primero.", `pushDenied` "Bloqueaste las notificaciones; habilitalas desde la configuración del navegador.", `pushEnabled` "Notificaciones activadas".
2. `components/app-shell/notification-bell.tsx` (`'use client'`):
   - A bell icon in the top bar with an unread count badge; the initial count is passed from the server.
   - Subscribe via the browser Supabase client to `postgres_changes` INSERT on `notifications` filtered `user_id=eq.<me>`: increment the count and show a sonner toast with title/body and an action to open the url. Unsubscribe on unmount.
   - Links to `/notificaciones`.
   - Add it to `components/app-shell/top-bar.tsx` (the server part loads the unread count with `head: true`).
3. `app/notificaciones/page.tsx` (RSC): my last 50 notifications, newest first. Unread ones are highlighted. Each item links to `payload.url` (same-origin paths only: validate it starts with `/` and not `//`, else no link) and shows a relative time. Add a "Marcar todas como leídas" button (client) → `markNotificationsRead()` → `router.refresh()`. Opening an item marks that id read.
4. `app/yo/ajustes/page.tsx` + `components/notifications/prefs-form.tsx` (`'use client'`): a switch per kind → `updateNotificationPrefs` (optimistic + toast on error), plus a push section driven by `lib/push/client.ts` states (unsupported / denied / enabled / disabled). Link to it from the user menu and from `/yo`.
5. Pure helper `lib/notifications/safe-url.ts` (`safeInternalUrl`) with tests (rejects `//evil.com`, `https://…`, `javascript:`).
6. Tests: `lib/notifications/safe-url.test.ts`, `components/notifications/prefs-form.test.tsx` (toggle calls the action with merged prefs; push states), `components/app-shell/notification-bell.test.tsx` (the count renders; mock the Supabase client channel).
