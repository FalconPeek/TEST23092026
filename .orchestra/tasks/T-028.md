## Context
T-018 (bracket view + match result actions + realtime) was **rejected**; see `.orchestra/reports/T-018.verify.md`. Everything else passed: realtime, admin gating, layout.

The bug: in double elimination with a grand final reset, when the losers-bracket team wins GF1, GF2 (the reset) becomes pending. But `lib/tournament/bracket-layout.ts` (~line 204) already declares GF1's winner the champion, and the `llave` page doesn't gate the banner on the tournament being finished. The champion can show too early and be wrong. Keep the T-018 files in place and fix them in place.

## Steps
1. `lib/tournament/bracket-layout.ts`: the champion is resolved only when every final-type match is decided. That means GF2 must be `completed` when it's active (both entries set); if GF2 is `archived` (the winners-bracket team won GF1), GF1 decides. For single elim it's the `final` match's `winner_entry_id`, and a third-place match never decides the champion. Return `null` while any final is unresolved.
2. `app/g/[groupId]/torneos/[tournamentId]/llave/page.tsx`: render the champion banner only when `tournaments.status === 'finished'` AND the layout returns a champion.
3. Tests in `lib/tournament/bracket-layout.test.ts`:
   - DE where the LB team wins GF1 with GF2 pending → no champion;
   - GF2 completed → the GF2 winner is champion;
   - the WB team wins GF1 (GF2 archived) → the GF1 winner is champion;
   - SE with a pending final → null.
