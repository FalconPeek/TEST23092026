## Context
Tournament entries can now be clubs: `tournament_entries.club_id`. `saveTournamentEntries` (`lib/actions/tournaments.ts`) accepts an optional `clubId` per entry; the RPC checks the club belongs to the group. Clubs have a name, colors, a crest and a roster (T-029, `components/clubs/club-crest.tsx`).

## Steps
1. `messages/es.ts`: `tournament.useClub` "Usar club", `tournament.noClub` "Sin club".
2. `components/tournament/entries-editor.tsx` (T-017):
   - Each team gets a club select.
   - Picking a club sets the entry name to the club's name and prefills its players from the club roster, minus players already in other entries. The admin can still edit players afterwards.
   - Clearing the club keeps the name and players.
   - The payload includes `clubId`.
   - Update `lib/tournament/entries.ts` (+ tests) if the pure helpers need a `clubId` field.
3. Show `ClubCrest` (sm) next to entry names wherever entries render: the hub teams list, `components/tournament/bracket-view.tsx`, `components/tournament/standings-table.tsx`, and `components/tournament/fixtures-list.tsx`. Pass a `clubsById` map from the pages (one query for the group's clubs).
4. Tests: extend `components/tournament/entries-editor.test.tsx` (choosing a club prefills name and roster and sends `clubId`; roster players already used elsewhere are skipped). Also a render test that a crest shows in the standings row when the entry has a club.

- No player ends up in two entries.
