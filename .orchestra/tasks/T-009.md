## Context
"Everything configurable": group settings are `groupSettingsSchema` in `lib/settings/group.ts` (zod 4; nested `rating`, `rating.form`, `rating.rate_limit`, `scouting`, `windows`, `tiers`, `playstyles`, plus `default_team_size`, `badges_enabled`, `spectators_can_rate`). Stored in `groups.settings` (jsonb, may be partial) — always read with `parseGroupSettings(raw)`. Saved via `updateGroup({ groupId, name, settings })` (admins only). Players edit their own profile via `updateMyPlayer` (display name, primary position, up to 4 alternate positions, preferred foot, height).

## Steps
1. `messages/es.ts`: add `groupSettings.*` labels + short help texts for each setting a normal organizer cares about: name, default team size, report window hours, rating window hours, spectators can rate, spectator weight, min raters for a definitive card, tier thresholds (silver/gold/special), special on last-match MVP, scouting revote days, require shared match to scout, badges enabled. And an "Avanzado" section title + help ("Parámetros del algoritmo de puntaje. Tocá solo si sabés lo que hacés."). Add `player.*` for the profile editor (Posición principal, Posiciones alternativas, Pie hábil, Altura (cm), Nombre visible, Guardar).
2. `components/settings/group-settings-form.tsx` (`'use client'`): form bound to the parsed settings; common fields as proper inputs (number inputs, switches, select for team size 5/6/7/8/9/11); an "Avanzado" collapsible with every remaining numeric `rating.*` field auto-rendered by walking the zod-parsed object (label = key, humanized; number input with step) so new tunables appear without UI changes. Client-side validate with `groupSettingsSchema.safeParse` and show field errors; submit calls `updateGroup`; "Restaurar valores por defecto" button resets the form to `defaultGroupSettings`.
3. Add a "Configuración del grupo" section at the top of `app/g/[groupId]/ajustes/page.tsx` for admins rendering the form (read-only summary for non-admins is NOT needed — just hide it).
4. `app/g/[groupId]/jugadores/[playerId]/editar/page.tsx`: only the player's own user (or an admin, for guests) may open it, else `notFound()`. `components/player/player-profile-form.tsx` (`'use client'`): name, primary position (select of 15 with `es.positions`), alternate positions (toggle chips, max 4, excluding primary), preferred foot (radio `es.foot`), height (optional). Submit → `updateMyPlayer` or `updatePlayer` (guest edited by admin). Link to it from the group home members preview for "my" player ("Editar mi perfil").
5. Tests: `components/settings/group-settings-form.test.tsx` (renders defaults, invalid value blocks submit and shows an error, reset restores defaults) and `components/player/player-profile-form.test.tsx` (max 4 alternates, primary excluded).

## Acceptance criteria
- Settings round-trip: save → reload shows saved values; untouched fields keep defaults; invalid values never reach the server action.
- Advanced section renders every numeric rating tunable automatically.
- Profile editor enforces the same constraints as the SQL (positions in the 15 codes, ≤4 alternates, height 120–230).
