## Context
Admins share `${siteUrl}invitacion/<code>`. `/invitacion/*` is a public path in `proxy.ts` (so we can show a friendly page), but joining requires sign-in. RPC `get_invite_preview(p_code)` (authenticated only) returns `{ group_id, group_name, role, member_count, valid }` (zero rows for an unknown code). Joining uses `acceptInvite({ code })` from `lib/actions/groups.ts` (idempotent if already a member).

## Steps
1. `messages/es.ts`: add `invite.*`: `title` ("Te invitaron a un grupo"), `joinAs` (function `(role) => …` using `es.roles`, e.g. "Vas a entrar como Jugador"), `join` ("Unirme"), `signInToJoin` ("Entrá para unirte"), `invalid` ("Esta invitación no es válida o ya venció."), `goHome` ("Ir a mis grupos").
2. `app/invitacion/[code]/page.tsx` (Server Component): validate `code` format (url-safe, 6–32 chars) else show invalid state. If not signed in → show the title and a button to `/login?next=/invitacion/<code>` (no DB call). If signed in → call `get_invite_preview`; if no row or `valid=false` → invalid state with link to `/g`; else show group name, member count, role and a join button.
3. `components/invite/join-button.tsx` (`'use client'`): calls `acceptInvite`, pending state, on success `router.replace('/g/'+groupId)` + toast `es.groups.joined`, on error toast the mapped message.
4. Test: `components/invite/join-button.test.tsx` (success navigates, error toasts; mock the action, `next/navigation`, `sonner`).

## Files

## Acceptance criteria
- Unauthenticated visitors never trigger an RPC and are sent back to the invite after login (`next` param).
- Invalid/expired/revoked codes show the invalid state, never an error page.
