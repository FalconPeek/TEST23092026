## Context
Members rate teammates' attributes. The rules are enforced in SQL:
- the rater must be a member and not a spectator;
- no self-votes;
- the target must not have left;
- the rater must have shared a played match with the target if the group setting requires it;
- one ballot per attribute, revotable every `scouting.revote_days`.

Useful RPCs:
- `get_scouting_status(p_target_player_id)` → `[{ can_vote, reason, next_vote_at }]`, where `reason` is one of `not_found | target_left | not_member | self | spectator | no_shared_match | cooldown | ok`.
- `get_my_scouting_ballot(p_target_player_id)` → my current rows `[{ attribute, value, mode, created_at }]`, used for prefill.

Actions from T-010 (`lib/actions/scouting.ts`): `submitScoutingVotes`, `submitPlaystyleVotes`, `submitStarVotes`.
- Quick mode votes the 6 face stats (`pac sho pas dri def phy`), each 1–10.
- Detailed mode votes sub-attributes (29 outfield, plus the 5 `gk_*` only when the target's primary/alt positions include POR).
- Playstyles: ≤5 from `PLAYSTYLES` (the GK-only ones only for GK targets).
- Stars: weak foot and skill moves, 1–5.

shadcn `slider`, `tabs`, `badge` and `button` are already in `components/ui`.

   - `reasons.*`, one string per `reason` (e.g. no_shared_match "Vas a poder votarlo cuando jueguen un partido juntos.", cooldown `(date) => "Podés volver a votarlo el {date}"` using `lib/format.ts`).
2. `components/scouting/vote-slider.tsx` (`'use client'`): label, 1–10 slider, the current value shown large, and a "sin votar" state until touched (detailed mode allows leaving it untouched; untouched keys are not sent).
3. `components/scouting/scouting-form.tsx` (`'use client'`). Props: target info (name, isGk), prefill ballot, canVote/reason, and group/target ids.
   - Quick/Detailed tabs: detailed groups the sliders under the 6 face stats (+ Arquero for GK) in collapsible sections.
   - A separate playstyles chip picker (max 5; filter to non-GK ones for outfield targets) with its own save button.
   - Stars (two 1–5 star pickers) with their own save button.
   - Each submit calls its action, shows a pending state, then `toast.success(es.scouting.saved)` or the error.
   - If `!canVote`, show the reason in an Alert and disable the vote inputs.
4. `app/g/[groupId]/jugadores/[playerId]/votar/page.tsx` (RSC): load the player (`notFound` if invisible), status, and ballot → render the form. Prefill: if my ballot is in quick mode, prefill quick; if detailed, prefill detailed and open that tab.
