## Context
The M1 schema is live on the local stack (migrations in `supabase/migrations/`, types in `lib/supabase/database.types.ts`). All writes go through SECURITY DEFINER RPCs; tables have **no** insert/update/delete grants. RPCs raise exceptions whose message starts with a stable prefix: `PICADO_FORBIDDEN:`, `PICADO_NOT_MEMBER:`, `PICADO_INVITE_INVALID:`, `PICADO_VALIDATION:` followed by an English detail (grep `supabase/migrations/*_group_rpcs.sql` for the exact texts). `lib/actions/result.ts` (T-003) provides `ActionResult`, `ok`, `fail`. Group settings are validated with `groupSettingsSchema` from `lib/settings/group.ts`.

Server Action rule (CLAUDE.md): zod-parse input → check auth (`getUserId()`; if null → `fail(es.errors.unauthenticated)`) → call the RPC with the user's session client (`lib/supabase/server.ts`; never the admin client) → `revalidatePath` → typed result. Never return raw DB errors.

## Steps
1. `messages/es.ts`: add namespaces
   - `errors`: `unauthenticated` ("Tenés que iniciar sesión."), `forbidden` ("No tenés permiso para hacer esto."), `notMember` ("No sos miembro de este grupo."), `inviteInvalid` ("La invitación no es válida."), `inviteExpired` ("La invitación venció."), `inviteRevoked` ("La invitación fue revocada."), `inviteUsedUp` ("La invitación ya alcanzó su límite de usos."), `validation` ("Revisá los datos ingresados."), `ownerCannotLeave` ("Transferí el grupo a otro miembro antes de salir."), `ownerCannotBeRemoved` ("No se puede quitar al dueño del grupo.").
   - `groups`: strings needed by the actions' success toasts (e.g. `created` "Grupo creado", `updated` "Cambios guardados", `inviteCreated` "Invitación creada", `inviteRevoked`, `joined` "¡Te sumaste al grupo!", `roleChanged`, `memberRemoved`, `left`, `guestAdded`, `guestClaimed`, `ownershipTransferred`, `playerUpdated`). (Later UI tasks add more `groups.*` keys.)
2. `lib/actions/errors.ts`: `export function mapDbError(error: { message?: string } | null | undefined): string` → maps by prefix, and for `PICADO_INVITE_INVALID` / `PICADO_FORBIDDEN` also by known detail substrings (expired / revoked / usage limit / "transfer ownership before leaving" / "owner cannot be removed") to the specific `es.errors.*` string; anything unknown → `es.common.error`. Pure function, colocated test `lib/actions/errors.test.ts` covering every branch.
3. `lib/actions/groups.ts` (`'use server'`), one exported async function per RPC, each accepting a plain typed object (not FormData) and returning `ActionResult<...>`:
   `createGroup({ name }) → { groupId }` · `updateGroup({ groupId, name, settings })` (parse `settings` with `groupSettingsSchema`; store the parsed object) · `createInvite({ groupId, role: "member"|"spectator"|"admin", expiresInDays: 1..90 | null, maxUses: 1..1000 | null }) → { id, code, url }` (url = `${siteUrl()}invitacion/${code}`) · `revokeInvite({ groupId, inviteId })` · `acceptInvite({ code }) → { groupId }` · `setMemberRole({ groupId, userId, role })` · `transferOwnership({ groupId, newOwnerId })` · `removeMember({ groupId, userId })` · `leaveGroup({ groupId })` · `addGuestPlayer({ groupId, displayName, primaryPosition? }) → { playerId }` · `claimGuestPlayer({ groupId, playerId })` · `assignGuestPlayer({ groupId, playerId, userId })` · `updateMyPlayer({ groupId, displayName, primaryPosition?, altPositions?, preferredFoot?, heightCm? })` · `updatePlayer({ groupId, playerId, ... })`.
   zod: uuids via `z.uuid()`, names trimmed 1–60, positions `z.enum` of the 15 codes (import the list from `lib/rating/positions.ts` `POSITIONS`), alt positions max 4 unique and not containing the primary, height 120–230 int. `revalidatePath` for `/g` and/or `/g/${groupId}` (layout) as appropriate.
4. `lib/actions/groups.test.ts`: mock `@/lib/supabase/server` (`createClient` returning an object with `rpc` vi.fn; `getUserId`) and `next/cache`. Test: invalid input never calls rpc; unauthenticated returns `es.errors.unauthenticated`; happy path calls the right RPC with the right `p_*` args; RPC error is mapped (not leaked); `updateGroup` applies settings defaults.

## Acceptance criteria
- Every action: zod → auth → rpc → revalidate → `ActionResult`; no `any`; no admin client; no raw error strings returned.
- Admin role invites allowed in the input schema (the RPC enforces owner-only); `owner` never accepted as a role input.
