## Context
`tournament_matches` rows hold:
- `bracket` (winners | losers | final | third | group | swiss), `round`, `number`;
- `entry1_id`/`entry2_id`, stored as text: a `tournament_entries.id`, the literal `"__bye__"`, or null for "to be decided". `entry1_from`/`entry2_from` jsonb `{fromGroup, rank}` name a groups_ko qualifier placeholder;
- `status` (locked | waiting | ready | in_progress | completed | archived);
- `score1`/`score2`, `pens1`/`pens2`, `decided_by`, `winner_entry_id`;
- `next_match_id`, `match_id` (the linked real match).

Actions (`lib/actions/tournaments.ts`):
- `startTournamentMatch({ tournamentMatchId, tournamentId, groupId, scheduledAt, venue? })`: admin, match `ready`. It creates the real match with both teams' lineups. The result then flows through the normal report → finalize path, and the finalizer auto-advances the bracket.
- `confirmTournamentResult({ …, score1, score2, pens1?, pens2?, decidedBy?: 'manual'|'walkover', winnerEntryId? })`: an organizer's manual result, e.g. a KO draw after `PICADO_KO_DRAW`, or a walkover.
- `editTournamentResult(...)`: same input; only allowed while downstream matches haven't started.

**Realtime:** `tournament_matches`, `tournaments` and `matches` are in the `supabase_realtime` publication (RLS-filtered). Subscribe with the browser client (`lib/supabase/client.ts`) to `postgres_changes` filtered by `tournament_id=eq.<id>`, and call `router.refresh()` (debounced ~500 ms). Unsubscribe on unmount.

## Steps
1. `messages/es.ts`: add `bracket.*`:
   - `winners` "Llave principal", `losers` "Llave de perdedores", `final` "Final", `grandFinal` "Gran final", `reset` "Final (desempate)", `third` "Tercer puesto";
   - `round` `(r, total) => …` (use "Final"/"Semifinal"/"Cuartos"/"Octavos" by distance to the final, else "Ronda r"), `bye` "Libre", `tbd` "A definir", `fromGroup` `(label, rank) => "{rank}º Grupo {label}"`;
   - `play` "Programar partido", `goToMatch` "Ver partido", `enterResult` "Cargar resultado", `editResult` "Corregir resultado", `walkover` "Ganó por W.O.", `pens` "Penales", `champion` "¡Campeón!".
2. Pure `lib/tournament/bracket-layout.ts`: turns match rows into columns per bracket/round sorted by `number`, with round labels. It resolves entry display (name / Libre / A definir / qualifier placeholder) and marks the champion. Tests cover SE 8 with byes, DE 4 with GF reset, and SE with a third-place match.
3. `components/tournament/bracket-view.tsx` (server-safe): horizontally scrollable columns (snap scrolling on mobile) with a section per bracket. Each match card shows two rows (entry name, score, pens in small text, the winner in bold, byes muted), a status chip, and a link to the real match when `match_id` is set.
4. `components/tournament/match-admin-menu.tsx` (`'use client'`, admin only):
   - "Programar partido" (ready matches without `match_id`) opens a dialog with datetime + venue → `startTournamentMatch`, then navigates to the real match lineup page.
   - "Cargar resultado" / "Corregir resultado" open a dialog with score steppers. Pens fields appear when the scores are tied and the match is KO. A walkover toggle takes a winner select. Submits `confirmTournamentResult` / `editTournamentResult`.
5. `components/tournament/tournament-realtime.tsx` (`'use client'`): the subscription described above; renders nothing.
6. `app/g/[groupId]/torneos/[tournamentId]/llave/page.tsx`: load matches + entries (session client) → layout → `BracketView` + realtime, with a champion banner when finished. For groups_ko, render only the KO stage here.
7. Tests: `lib/tournament/bracket-layout.test.ts`, and `components/tournament/match-admin-menu.test.tsx` (pens fields only on a tied KO; the walkover requires a winner).

## Acceptance criteria
- Byes and TBD slots render clearly. There's no horizontal page scroll: only the bracket container scrolls.
- Results update live in a second browser tab without a manual reload, via realtime + `router.refresh()`.
- The winner is never computed client-side: the display comes from `winner_entry_id`.
