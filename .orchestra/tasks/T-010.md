## Context
The M2/M3 schemas are live. Every vote/report write goes through a SECURITY DEFINER RPC (signatures are in `lib/supabase/database.types.ts` → `Functions`). Follow **exactly** the pattern of `lib/actions/groups.ts` (T-005): zod `safeParse` → `getUserId()` → session `createClient()` → `supabase.rpc(...)` → `fail(mapDbError(error))` on error → `revalidatePath` → `ActionResult`. There is never an admin client in these actions, with one exception: `recomputeNow` (below), which is a server-only helper that already uses the admin client internally.

Card refresh: after a scouting/playstyle/star vote succeeds, call `recomputeNow([targetPlayerId])` from `lib/server/recompute-now.ts` inside `try/catch`. If it throws, still return `ok`: DB triggers also enqueue the player in `recompute_queue`, and the cron drain catches up. Add a one-line comment saying that.

Finalizing matches is NOT part of this task: FATHER provides `finalizeMatchNow` in `lib/actions/finalize.ts`.

RPC payload shapes (from the migrations):
- `create_match(p_group_id, p_scheduled_at timestamptz ISO, p_team_size int, p_venue?)` → match uuid. Admin only.
- `set_match_lineup(p_match_id, p_team1, p_team2, p_spectators uuid[])`. `p_teamN = { name, color?, players: [{ player_id, position? }] }` where position is one of the 15 codes or omitted. Admin only.
- `start_reporting(p_match_id, p_played_at?)` and `cancel_match(p_match_id)`: admin only.
- `submit_score_report(p_match_id, p_team1_goals, p_team2_goals)`.
- `submit_stat_reports(p_match_id, p_reports)` with `p_reports = [{ subject_player_id, goals, assists, own_goals, saves }]`. Unique subjects. goals/assists/own_goals 0–30, saves 0–99.
- `submit_match_ratings(p_match_id, p_ratings)` with `p_ratings = [{ target_player_id, rating 1–10, standout_attributes: string[] (≤2 sub-attribute keys) }]`.
- `resolve_dispute(p_match_id, p_team1_goals, p_team2_goals, p_stats?)` with `p_stats = [{ subject_player_id, goals?, assists?, own_goals?, saves? }]`. Admin only.
- `submit_scouting_votes(p_target_player_id, p_mode 'quick'|'detailed', p_votes)` with `p_votes = { key: 1–10 }`. Quick keys: `pac sho pas dri def phy`. Detailed keys: the 29 outfield sub-attributes, plus `gk_*` only when the target is a GK (the RPC enforces that part).
- `submit_playstyle_votes(p_target_player_id, p_playstyles text[])`: ≤5 codes, unique, from the known list.
- `submit_star_votes(p_target_player_id, p_weak_foot 1–5, p_skill_moves 1–5)`.
