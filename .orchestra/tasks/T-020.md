## Steps
1. `components/settings/group-settings-form.tsx`: a cleared number input must not become `0`. Keep the raw string in form state (or `NaN`) so `safeParse` reports a field error ("Completá este campo"; add `groupSettings.required` to `es.ts`).
2. "Avanzado" labels: add `es.groupSettings.advanced` with Spanish labels for every numeric `rating.*` leaf in `lib/settings/group.ts`. The form uses the label when present and falls back to the humanized key, so future tunables still render.
3. `components/player/player-profile-form.tsx` + `lib/actions/groups.ts` `updateMyPlayer`/`updatePlayer`: allow clearing height and preferred foot.
   - First read `private.apply_player_update` in `supabase/migrations/*group_rpcs.sql` to see how null is treated.
   - If the RPC can't distinguish "clear" from "keep", do NOT change SQL: note it in your report and implement only the UI side (explicit "Sin especificar" option) that sends what the RPC supports.
4. Transfer-ownership select (`components/settings/danger-zone.tsx`): list admins and members only (exclude spectators), for a clearer UX.
5. From `.orchestra/reports/T-011.verify.md`:
   - The profile's "Media por posición" chips show the raw code; label them with `es.positions`.
   - The attribute bars use raw Tailwind colors; switch to theme tokens (add `--stat-low/mid/good/great` in `app/globals.css` `@theme` if missing).
   - The empty stats state reuses `groups.noMatches`; add `profile.noStats`.
6. From `.orchestra/reports/T-012.verify.md` (this one changes rating integrity, so it matters most):
   - In quick mode, untouched sliders currently send a default of 5, which biases cards toward 62.5.
   - Quick mode must behave like detailed mode: untouched face stats stay "sin votar" and are NOT sent, with at least 1 touched required to save.
   - Prefilled values from the existing ballot count as touched.
   - Update `components/scouting/scouting-form.tsx` and its test. This supersedes T-012's "quick mode always sends all 6".
7. Test infra: move the per-file ResizeObserver / pointer-capture stubs used by the slider/radar tests into the shared `vitest.setup.ts`, and remove the per-file copies.
8. Update the related tests.
